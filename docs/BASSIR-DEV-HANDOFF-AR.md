> وثيقة تسليم شاملة: ماذا بُني، أين يقع في الكود، وكيف يتأكّد المبرمج أنّ كل ما هو مطلوب نُفّذ.
> آخر تحديث: أكتوبر 2026 · الفرع: `claude/bassir-owner-eyes-system-aogee5` → مدموج في `main`.

## 1) نظرة عامة

**بصير — عيون المالك** منصّة سعودية لمراقبة المشاريع الإنشائية بصرياً، تربط المالك وممثّله والاستشاري والمقاول في مكان واحد. فوقها طبقة تجارية **«بصير بزنس»** تتيح بيع النظام للعملاء باشتراك شهري لكل مشروع.

- **الواجهة:** JavaScript خالص بلا خطوة بناء (تُحمَّل السكربتات بالترتيب من `public/index.html`).
- **النواة المشتركة:** `shared/api-core.js` + `shared/seed-data.js` تعمل في خادم Node وفي المتصفّح (وضع الديمو).
- **الخادم:** `server/server.js` (Node، قاعدة SQLite، رفع ملفات، CSP).
- **التسعير:** **2,000 ر.س لكل مشروع / شهرياً** (مشروعان = 4,000، ثلاثة = 6,000… ).

### حسابات الدخول
| الحساب | المستخدم / المرور | الدور |
|---|---|---|
| المالك | `owner / owner123` | owner |
| ممثل المالك | `rep / rep123` | owner_rep |
| الاستشاري | `consultant / consult123` | consultant |
| مدير المشروع | `pm / pm123` | project_manager |
| مقاول معماري | `cont-arch / cont123` | contractor |
| مقاول إنشائي | `cont-str / cont123` | contractor |
| الأدمن | `admin / admin123` | admin |
| **مالك المنصّة** | `biz / biz123` | **platform_admin** (دخول مخفيّ) |

## 3) ماذا بُني — طبقة «بصير بزنس» التجارية (محور التسليم)

### 3.1 لوحة مالك المنصّة (قسم «بصير بزنس» — يظهر فقط لدور `platform_admin`/`admin`)
| الصفحة | المحتوى | الملف/الدالة |
|---|---|---|
| لوحة المنصّة | MRR/ARR، الإيراد المحصّل، المشتركون الفعّالون، المستحقّات، **🚀 نمو النظام**، **🧲 قمع التحويل**، رسم الإيراد الشهري، توزيع الحالات، بطاقات القيمة لكل دور، زر «تشغيل الفوترة» | `renderPlatformOverview` |
| المشتركون | جدول الشركات: الباقة، عدد المشاريع، قيمة الاشتراك (شهري+سنوي)، **مدّة الاشتراك (بداية→نهاية)**، الحالة، آخر دفع والتجديد، تفعيل/إيقاف، فواتير، إضافة مشترك | `renderTenants` |
| الفواتير والتحصيل | كل الفواتير + تحصيل أي فاتورة | `renderInvoices` |
| الباقات والتسعير | الباقات ومزاياها | `renderPlans` |

الكود كله في `public/js/views-platform.js` (كائن `window.ViewsPlatform`).

### 3.2 الدخول المخفيّ لمالك المنصّة
- في صفحة الدخول: **الضغط ثلاث مرّات على شعار العين 👁** يكشف زرّ «بوّابة مالك المنصّة».
- لا يظهر لأي مستخدم عادي؛ الحركة يعرفها الأدمن فقط. الكود في `public/js/app.js` (داخل `renderLogin`، عنصر `#plat-gate` + وِصال `#lg-logo`).

### 3.3 صفحة الهبوط (التسويق + الشراء)
الملف: `public/landing.html` + السكربت الخارجي `public/js/landing.js` (العنوان `/landing.html`).
- Hero + القيمة لكل دور + **كيف يعمل**.
- **🧮 حاسبة العائد (ROI):** يُدخل العميل قيمة مشروعه وعدد مشاريعه فيرى التوفير السنوي التقديري (منع تجاوز الميزانية ~3٪ + تقليل الهدر ~1.5٪ + تسريع الاعتماد ~0.5٪) مقابل تكلفة الاشتراك، ومضاعف العائد.
- قسم **«لماذا بصير هو الخيار التقني المناسب»**.
- التسعير + حاسبة سعر حيّة + **نموذج تسجيل ودفع ببطاقة** (معاينة بطاقة حيّة) → تفعيل فوري.
- تعمل مع الخادم، وتسقط تلقائياً على نواة المتصفّح للعرض الثابت.

### 3.4 محرّك الفوترة والتفعيل الآلي (`shared/api-core.js`)
- `platformStats()` — يحسب كل المؤشّرات (انظر 4.3).
- `recordVisit()` — يزيد عدّاد زيارات صفحة الهبوط (قياس التحويل).
- `registerTenant(payload)` — تسجيل عام → حالة `pending`.
- `subscribeTenant(payload)` — دفع عام → تفعيل + فاتورة مدفوعة + تحديد بداية/نهاية الاشتراك.
- `createTenant(user,payload)` — إنشاء من اللوحة.
- `payTenantInvoice(user,invoiceId,card)` — تحصيل فاتورة (يعيد تفعيل الموقوف).
- `setTenantStatus(user,tenantId,status,reason)` — تفعيل/إيقاف يدوي.
- `runBilling(user)` — **التفعيل/الإيقاف الآلي:** يُصدر فواتير الاستحقاق، يعلّم المتأخرة، ويوقف غير المسدِّدين؛ والدفع يعيد التفعيل.

## 4) البنية التقنية (للمطوّر)

### 4.1 الملفات المعنيّة بطبقة المنصّة
- `shared/seed-data.js` — الباقات، المستأجرون، الفواتير، مستخدم `biz`، `db.meta.landingVisits`، الإصدار **v23**.
- `shared/api-core.js` — محرّك الفوترة والإحصاءات (ثابت `DEFAULT_PRICE = 2000`).
- `public/js/api.js` — توجيه الديمو + دوال `Api.platform*`.
- `server/server.js` — مسارات المنصّة + سياسة أمان المحتوى (CSP).
- `public/js/views-platform.js` — لوحات المالك الأربع.
- `public/js/app.js` — دور `platform_admin`، الصفحات الأربع، والبوّابة المخفيّة.
- `public/landing.html` + `public/js/landing.js` — صفحة الهبوط.

### 4.2 المسارات (API)
**عامة (بلا مصادقة — لصفحة الهبوط):**
- `GET  /api/platform/plans`
- `POST /api/platform/visit`
- `POST /api/platform/register`
- `POST /api/platform/subscribe`

**لمالك المنصّة (تتطلّب `platform_admin`/`admin`):**
- `GET  /api/platform/state`
- `POST /api/actions/platform-create-tenant`
- `POST /api/actions/platform-pay-invoice`
- `POST /api/actions/platform-set-status`
- `POST /api/actions/platform-run-billing`

### 4.3 نموذج البيانات
**المستأجر (tenant):** `id, companyName, contactName, email, phone, planId, pricePerProject, projectCount, status (active|trial|suspended|pending), createdAt, activatedAt, subscriptionStart, subscriptionEnd, billingCycle, trialEndsAt, nextInvoiceDate, lastPaymentAt, usersCount, cardLast4, statusReason`.

**الفاتورة (invoice):** `id, number, tenantId, period, projectCount, pricePerProject, amount, currency, status (paid|unpaid|overdue), issuedAt, dueAt, paidAt, method, cardLast4`.

**مؤشّرات `platformStats`:** `tenants, active, trial, suspended, pending, projects, activeProjects, users, mrr, arr, totalRevenue, revThisMonth, newThisMonth, newLastMonth, mrrLastMonth, mrrGrowthPct, tenantGrowthPct, visits, buyers, leads, notBought, conversionPct, unpaid, overdue, outstanding, pricePerProject`.

## 5) نقاط يجب على المطوّر إكمالها قبل الإطلاق

1. **بوابة الدفع الحقيقية (الأهم):** الدفع الآن **مُحاكى** في دالة `chargeCard(card, amount)` بـ`shared/api-core.js` (تتحقّق فقط من طول رقم البطاقة). للإنتاج:
   - اربط **Moyasar** أو **Tap** (الأنسب للسوق السعودي، mada/Visa/Apple Pay).
   - **لا تمرّر رقم البطاقة للخادم:** استخدم توكن الدفع من مكتبة البوّابة في صفحة الهبوط، وأرسل الـ`token` فقط إلى `/api/platform/subscribe`، ونفّذ الدفع من الخادم بمفتاح `.env` (مثل `MOYASAR_SECRET_KEY`).
   - أضف **Webhook** لتأكيد الدفع (idempotent) وتحديث حالة الفاتورة/المستأجر.
   - راجع التفاصيل في `docs/SAAS-COMMERCIALIZATION.md`.
2. **جدولة الفوترة:** استدعِ `runBilling` يومياً عبر Cron/مهمة مجدولة (حالياً يدوي بزر في اللوحة).
3. **كلمة مرور مالك المنصّة:** غيّر `biz/biz123` لكلمة قويّة، واجعل البوّابة المخفيّة تطلب كلمة المرور بدل الدخول المباشر في الإنتاج.
4. **سياسة أمان المحتوى (CSP):** الخادم يمنع السكربت المضمّن (`script-src 'self'`). **أي سكربت جديد يجب أن يكون ملفاً خارجياً** يُحمَّل عبر `src` (كما في `js/landing.js`) — لا تضع `<script>…</script>` مضمّناً.
5. **البريد/واتساب للإشعارات:** عند الاشتراك/الإيقاف، أضف إشعاراً للعميل (التكامل موجود في `server/integrations` للنظام الأساسي).

## 6) ✅ قائمة التحقّق (يتبعها المبرمج للتأكّد من تنفيذ كل المطلوب)

> ضع ✔ أمام كل بند بعد تجربته على الموقع المنشور.

### أ) الدخول والصلاحيات
- [ ] تظهر صفحة الدخول بشعار العين والحسابات التجريبية.
- [ ] **الضغط ثلاث مرّات على شعار العين 👁** يُظهر زرّ «بوّابة مالك المنصّة» (وكان مخفياً قبلها).
- [ ] الضغط على الزر يُدخل كمالك المنصّة ويظهر قسم «بصير بزنس» في القائمة الجانبية.
- [ ] الحسابات العادية (مالك/استشاري/مقاول) **لا ترى** قسم «بصير بزنس».

### ب) لوحة مالك المنصّة
- [ ] صفحة «لوحة المنصّة» تعرض MRR والإيراد المحصّل وعدد المشتركين الفعّالين والمستحقّات.
- [ ] تظهر بطاقة **🚀 نمو النظام**: مشتركون جدد هذا الشهر مقابل الماضي (نسبة ▲/▼)، ونمو الدخل المتكرّر.
- [ ] تظهر بطاقة **🧲 قمع التحويل**: زوّار دخلوا النظام → سجّلوا → اشتركوا، مع **نسبة التحويل** وعدد **من زار ولم يشترِ** ومن **سجّل ولم يدفع**.
- [ ] يظهر رسم الإيراد الشهري وتوزيع المشتركين حسب الحالة.

### ج) المشتركون وبياناتهم
- [ ] صفحة «المشتركون» تعرض كل شركة: الاسم والمسؤول والبريد.
- [ ] لكل شركة: **الباقة، عدد المشاريع، قيمة الاشتراك (شهري + سنوي)**.
- [ ] لكل شركة: **مدّة الاشتراك (تاريخ البداية → تاريخ النهاية)**.
- [ ] لكل شركة: الحالة (فعّال/تجريبي/موقوف/بانتظار الدفع)، وآخر دفع والتجديد القادم.
- [ ] زر **«إضافة مشترك»** يفتح نموذجاً ويُضيف شركة جديدة.
- [ ] زرّا **تفعيل/إيقاف** يغيّران حالة المشترك، وزر **«فواتير»** يعرض فواتيره.

### د) الفوترة والتفعيل الآلي
- [ ] صفحة «الفواتير والتحصيل» تعرض كل الفواتير بحالاتها (مدفوعة/غير مدفوعة/متأخرة).
- [ ] زر **«تحصيل»** يحوّل الفاتورة إلى مدفوعة ويعيد تفعيل الحساب الموقوف.
- [ ] زر **«تشغيل الفوترة»** يُصدر فواتير الاستحقاق ويوقف المتأخرين آلياً.

### هـ) صفحة الهبوط والشراء
- [ ] `/(موقعك)/landing.html` تفتح وتعرض القيمة لكل دور و«كيف يعمل».
- [ ] **حاسبة العائد (ROI):** إدخال قيمة المشروع وعدد المشاريع يُظهر **التوفير السنوي التقديري** وتكلفة الاشتراك و**مضاعف العائد** (كم ريال يوفّر لكل ريال).
- [ ] يظهر قسم **«لماذا بصير هو الخيار التقني المناسب»**.
- [ ] حاسبة السعر الحيّة تحسب (عدد المشاريع × 2,000).
- [ ] نموذج التسجيل + الدفع ببطاقة تجريبية (`4111 1111 1111 1111`) → تظهر رسالة **«تم تفعيل حسابك»** وتُنشأ شركة فعّالة بفاتورة مدفوعة.
- [ ] **مهم:** تأكّد أنّ كل وظائف صفحة الهبوط تعمل على **الخادم المنشور** (ليس محلياً فقط) — أي أنّ السكربت الخارجي يعمل تحت CSP.

### و) النمو والتحويل (الربط بصفحة الهبوط)
- [ ] فتح صفحة الهبوط يزيد عدّاد الزوّار (يظهر الأثر في «قمع التحويل» بلوحة المالك).
- [ ] العملاء الذين سجّلوا ولم يدفعوا يظهرون ضمن «سجّلوا ولم يدفعوا».

### ز) جاهزية الإنتاج (مهام المطوّر)
- [ ] رُبطت بوّابة دفع حقيقية (Moyasar/Tap) بدل المحاكاة، مع Webhook تأكيد.
- [ ] جُدولت `runBilling` يومياً (Cron).
- [ ] غُيّرت كلمة مرور `biz` وأصبحت البوّابة تطلب كلمة المرور.
- [ ] أي سكربت جديد خارجي (لا مضمّن) لاحترام CSP.
