1. Purpose of this document

The application is feature-complete and deployable. This document tells your developer what is left to do to take it live and beyond the demo — mostly provisioning, configuration, connecting real external services, and a few enhancements. It complements the two existing technical docs in the repo: docs/DEVELOPER-HANDOFF.md and docs/WHAT-WAS-ADDED-EN.md, and the deployment guides DEPLOY.md / DEPLOYMENT.md.

Priority key
P0 Go-live essentials (do before launch)  ·  P1 Real integrations & hardware  ·  P2 Enhancements & polish

2. What is already built & working

So the developer knows the baseline (no work needed here — verified, tests green):

  • Full 5-role system (owner, owner rep, consultant, contractor, admin) with per-role pages and data scoping.
  • Real backend: Node HTTP server (no framework), SQLite persistence (transactional, WAL) via node:sqlite — JSON fallback available. File uploads persisted to disk.
  • Authentication with signed tokens (JWT_SECRET), role-based authorization.
  • Real service integrations, each enabled by an env var and otherwise running in clearly-labelled simulation mode: Email (Resend/SendGrid), WhatsApp (Meta Cloud API), AI image analysis (Anthropic), camera snapshot ingress, RTSP live streaming (MediaMTX).
  • PDF reports generated server-side (pdfkit + Arabic reshaping).
  • In-browser viewers, fully offline: 3D BIM/IFC, vector DXF, and PDF drawings — no external/paid services.
  • Contractor BOQ & Schedule pages with file parsing (CSV/Excel/Primavera XER/P6 XML/PDF), baseline lock, and dual-approval revisions.
  • Progress Map that brightens dark → bright as work is completed and approved.
  • Saudi Arabia project map (newest feature — see §6).
  • Automated regression tests (Playwright) — smoke, full crawl (0 JS errors, all roles), brightness, end-to-end cycle, BIM render.

6. Newest feature — Saudi Arabia project map

Added to the owner dashboard (bottom) and the owner-rep portfolio page:

  • A real, offline map of the Kingdom (projected boundary baked into the code — no external map tiles).
  • One dot per project with traffic-light status: Green — on time & on budget Yellow — needs action (before red) Red — behind schedule or over budget
  • Click a dot → opens that project (switches the active project and its dashboard). Hover shows name, status, progress %, days behind, and budget overrun.
  • Coordinates are required when the owner rep adds a project (validated to be inside the Kingdom), with a 29-city quick-picker that auto-fills lat/lng. Existing projects can be given coordinates in Project Settings.

Code: map rendering + status logic in public/js/views.js (projectsMapHtml, mapStatus, baked KSA_PATH); add-project form in public/js/views2.js; edit/backfill in public/js/views4.js; lat/lng persisted in shared/api-core.js.

7. How to run & test

Run locally
npm install → npm start → open http://localhost:3000
Docker (recommended for the server) — see DEPLOY.md §3a.

Tests
npm run preflight — static checks
npm test — smoke + full crawl + brightness + cycle + BIM
Individual: npm run test:crawl, test:brightness, test:cycle, test:bim
